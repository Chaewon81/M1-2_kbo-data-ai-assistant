확인일: 2026-10-01. 데이터 CSV를 변경하지 않고 별도 검증했다.

## 결과

| 검증 대상 | 범위 | 결과 |
|---|---|---|
| 경기 내부 일관성 | 5,680개 팀 기록 / 2,840경기 | 검증한 항목 불일치 없음 |
| 공식 팀 기록 대조 | 4시즌 × 10팀 × 경기·승·패·무 | 160개 집계 모두 일치 |
| 공식 IP 상위 3명 선정 | 4시즌 × 10팀 | 40개 조합 모두 일치 |
| 투수 이름·G·IP·ER·ERA·WHIP·SO | 120개 시즌 기록 | 840개 항목 모두 일치 |

경기 내부 검사 항목은 경기·팀 키 중복, 점수와 W/L/D 일치, 완료 상태, 시즌 값, 양 팀의 날짜·시즌·구장·홈/원정·득실점 일치, 동일 날짜·팀·상대팀의 의심 ID 중복이다. 정상 더블헤더는 합치지 않는다.

공식 팀 순위 페이지와 투수 기록 페이지를 다시 조회했다. 투수 표는 기존 수집기의 고정 열 번호가 아니라 **열 제목을 기준으로 별도 파싱**하여 매핑 오류 가능성을 줄였다. 시즌·정규시즌·팀·정렬 조건도 확인했다. IP 변환 함수와 조회 폼 해석 일부는 기존 코드와 공유하므로 완전히 독립적인 수동 검증이라고 표현하지 않는다.

최종 실행의 1,060개 비교 항목: PASS 1,060 / MISMATCH 0 / UNVERIFIED 0. 처음 실행은 팀 순위의 연도 필드 이름을 잘못 찾아 집계 대조 4개가 미확인이었고, `ddlYear`로 보완한 뒤 재실행했다. 첫 보고서는 이력으로 보존했다.

## 증빙

- 최종 비교표: [comparisons.csv](20261001_142710/comparisons.csv)
- 실행 요약·HTML SHA-256: [summary.json](20261001_142710/summary.json)
- 같은 폴더의 `rank_YYYY.html`, `pitcher_YYYY_TEAM.html`: 당시 공식 페이지 HTML
- 각 비교 행에는 시즌·팀·항목·수집값·공식값·차이·출처·확인 시각·증빙 파일·판정을 기록했다. 확인 시각은 검증 실행 시작 시각이다.

출처: [KBO 연도별 팀 순위](https://www.koreabaseball.com/Record/TeamRank/TeamRank.aspx), [KBO 투수 기록](https://www.koreabaseball.com/Record/Player/PitcherBasic/Basic1.aspx). 시즌별 POST 조건과 응답은 저장 HTML에 남겼다.

## 아직 확인하지 못한 범위

- 개막·최종·무승부·더블헤더·재편성 경기의 **별도 게임센터 상세 대조**. 게임센터 페이지 접근 및 별도 목록 요청에서 오류 페이지가 반환되어 상세 일치로 판정하지 않았다.
- 이적 선수의 공식 시즌 통계가 팀별 재적 기간만의 분할 기록인지 여부.
- 경기 집계가 같더라도 모든 경기의 개별 점수가 공식 상세 기록과 같다는 보장은 아니다.
- 공식 사이트의 갱신 지연과 수집 이후 기록 정정. 2026 데이터는 이번 조회 시점의 집계와 일치한다.
- 브라우저 표시·Firestore 적재·배포·AI 응답의 정확성은 이 데이터 대조와 별도 검증이다.

## 다시 실행

프로젝트 루트에서 실행한다. 기존 데이터는 덮어쓰지 않고 실행마다 새 보고서 폴더를 만든다.

```powershell
python -m backend.scripts.audit_kbo_data --official
```

인터넷 없이 내부 검사만 하려면 `--official`을 생략한다. 이것은 공식 일치 검증을 뜻하지 않는다. 불일치 또는 미확인 항목은 `comparisons.csv`의 `verdict`로 구분하고, 원인 확인 전 데이터는 수정하지 않는다.
